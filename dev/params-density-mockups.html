A — step to 4 columns on wide blocks

One CSS change: cap --fb-cols at 4 and let a container query step down. Everything fits one row here, but a select with many picks still wraps tall — narrower columns can even make that worse.

B — one-line selects with an overflow counter

The multi-select never wraps: it shows the chips that fit on one 42px line and folds the rest into a +N counter. The full chip list lives in the open dropdown, where there is room. Every field is exactly one row tall, so the grid is a calm lattice whatever the pick counts.

C — summary text, chips only when open

The closed control is quieter still: the joined values as plain text with a count pill, no chips at all. Reads like a sentence, edits like a dropdown. The trade: you cannot remove one pick without opening it.

D — label inside the border

The label row is half of every field's height. Move it onto the border (notched, 11px) and the band flattens by ~20px per row. Combines with B or C.

E — row layout past a threshold

When a script declares more than ~6 controls, a grid stops scanning well whatever the density. Switch to label-left rows at 36px: reads like a settings form, every value stays fully visible, and vertical growth is honest — one row per control.
